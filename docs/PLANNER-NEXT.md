# План 0.9.22+: планер билдов. Расчёты заморожены

**Решение (зафиксировано):** PoеBuilder — это **планер билдов**: дерево, снаряжение, самоцветы,
умения, награды актов, иконки. Расчёт урона и прочие расчёты **замораживаются на неопределённое время**:
они остаются как есть (v1, с честными «не учтено»), новые формулы не добавляются, паритет с PoB2 по
урону не ведётся. Вся работа — про **полноту и наглядность плана**.

Следствия:

- Данные важнее математики: если мод/строка/вариант/иконка есть в проверенных данных — они должны быть
  в плане и видны, даже если в расчёт не входят.
- Ничего не выдумывать: отсутствующее честно помечается (пустой слот, «нет данных», подпись в UI).
- Расчётные модули (`Character/*`, `Calculation/*`) не трогаем, кроме случаев, когда правка нужна
  планеру (например, чтобы текст уники корректно разбирался для показа).

## Что закрыто на этот момент (контекст для планирования)

Дерево: фон PoB2, слои классов и восхождений, портреты, рамки узлов из атласа PoB2, эффект-паттерны
мастери, коннекторы по орбитам, радиус самоцветов, цвета наборов оружия, тултип узла с вкладом,
поиск. Снаряжение: базы, пулы модов, редкости, осквернение, руны/ядра/идолы, гнёзда, слоты в духе
инвентаря, экспорт/импорт. Камни: каталог 1115, группы с поддержками. Награды актов: таблица PoB2.
Иконки: 1355 файлов (базы, камни, часть уников).

## Этап 1. Уникальные предметы: полные моды (сделано в 0.9.22)

Цель: у уники в планере видны **все** её строки, включая выбор варианта, — не «впиши текст руками».

- [x] `UniqueItemText` (ядро): варианты (`Selected Variant` / `Current`), отбор строк по варианту,
      разбиение на имплиситы/эксплиситы по `Implicits: N`, перевод диапазонов `(10-20)` в максимум,
      сборка текста предмета и разбор чужого текста обратно в строки с типами.
- [x] Редактор предмета: список вариантов уники (Morior Invictus — 29), строки выбранного варианта,
      правка значений, генерация заметок из строк, превью-тултип уники в цветах игры (был пустым).
- [x] Явные метки строк: «вариант N» и «тег: …» (в редакторе).
- [ ] Перенести строки уники в отдельное поле плана (схема 5), чтобы мод-лист не терял структуру и его
      можно было показывать в списке снаряжения и тултипе слота так же, как в редакторе.

## Правила ведения работы

1. Каждый пункт закрывается тестом (ядро) или проверкой запуска (UI) и записью в `VALIDATION.md`.
2. Новых формул урона не добавляем; если строка уники не распознаётся расчётом — это нормально и
   помечено в UI.
3. Данные (каталог, уники, дерево, награды) меняются только вместе с их пинованным хешем и NOTICE.
4. UI проверяется скриптом, а не глазами: `PoeBuilder.exe --check-windows` собирает редакторы против
   закреплённых данных, раскладывает их вне экрана, прогоняет черновики и печатает результат с кодом
   возврата. Набор тестов работает на чистом .NET без WPF и ошибку XAML увидеть не может.
   Для дерева есть парный ключ `--render-tree` (снимки `tree-*.png` для сравнения с PoB2).
